## الباب الأول: الهوية الفلسفية والقواعد المعمارية الصارمة الـ 22

### 1.1 فلسفة المعالجة المحلية التامة (Local-First Architecture)
صُممت منظومة **ZaWolf** لتكون منصة استيعاب وتخزين للبيانات الطبية غير المتجانسة (الروشتات الورقية، التحاليل المعملية، تقارير الأشعة، الفحوصات الإحصائية). تنطلق المنظومة من مبدأ **السيادة التامة على البيانات (Data Sovereignty)**؛ حيث لا يُسمح بتسريب أي معلومة طبية أو اسم مريض إلى خوادم خارجية أو واجهات سحابية تجارية، مما يضمن الامتثال الكامل لقوانين الخصوصية الطبية الدولية.

### 1.2 دستور المنظومة المعماري (System Invariants):
1. **كشف نوع الملف مبني على القواعد:** تحديد نوع الملف يعتمد حصرياً على امتداد الملف وليس بالتخمين.
2. **التوجيه حتمي (Deterministic Routing):** يقرر موجه المسارات المسار المناسب لكل ملف بشكل قاطع.
3. **تحويل PDF الممسوح ضوئياً إلى صور:** صفحات الـ PDF الممسوحة ضوئياً تتحول فوراً إلى صور وتدخل مسار الصور نفسه.
4. **المسار الموحد للـ OCR:** لا توجد معمارية منفصلة للـ Scanned PDF؛ بل يستخدم نفس مسار الصور وموجه الـ OCR.
5. **معالجة مسبقة عامة للصور:** تخضع الصور لضبط التباين والتدوير والرمادية قبل التعرف الضوئي.
6. **ملفات Excel و CSV لا تمر على OCR نهائياً:** تستخرج بياناتها رقمياً عبر Pandas DataFrames في أجزاء من الثانية.
7. **ملفات Word لا تمر على OCR نهائياً:** تستخرج نصوصها وجداولها مباشرة عبر DOM الخاص بـ python-docx.
8. **ملفات PDF الرقمية تستخرج كنصوص مباشرة:** تستخرج نصوصها عبر PyMuPDF دون أي حاجة للـ OCR.
9. **وظيفة الـ OCR هي تحويل الصورة لنص خام فقط:** محرك الـ OCR لا يحلل ولا ينظم؛ دوره فقط استخراج النص.
10. **النموذج اللغوي (LLM) مشترك بعد الاستخراج:** كافة النصوص المستخرجة تتجمع وتدخل نفس محرك الـ LLM الموحد.
11. **الـ LLM ينظم ويوحد ولا يخترع:** دور الـ LLM هو تنظيف وتوحيد وتعيين الحقول، وممنوع عليه منعاً باتاً اختراع أي معلومة طبية ناقصة.
12. **الحفاظ على القيم المفقودة:** أي معلومة غير مذكورة في الأصل تترك `null`.
13. **عدم تنظيف ملفات Excel/CSV أثناء الاستخراج الأولي:** تترك كما هي لضمان مطابقة الأصل.
14. **لا تحليل لجودة البيانات أثناء الاستخراج المبدئي:** الاستخراج يركز على سلامة القراءة فقط.
15. **التحقق (Validation) يتم بعد معالجة الـ LLM:** لا تدخل البيانات لقاعدة البيانات إلا بعد اجتياز فحص Pydantic.
16. **البيانات غير الصالحة تُرفض فوراً:** أي مستند غير مطابق يُوسم بـ `invalid` ولا يُسرب لقاعدة البيانات.
17. **قاعدة البيانات هي طبقة التخزين النهائية فقط:** لا يتم بناء منطق ذكاء اصطناعي داخل قاعدة البيانات.
18. **النمطية التامة (Modular System):** كل طبقة منفصلة تماماً ويمكن ترقية أي محرك دون المساس بباقي الطبقات.
19. **عزل الروشتات الطبية (Prescription Isolation):** تصفير الجداول غير الدوائية فور كشف أن المستند روشتة علاجية.
20. **المعاملات الذرية لقاعدة البيانات (Single Transaction Atomicity):** كل عملية حفظ تتم في اتصال واحد وتدعم التراجع التام (`Rollback`).
21. **تخريج المفاتيح الأجنبية يتم في طبقة قاعدة البيانات:** النموذج لا ينشئ معرّفات IDs، بل تتولاها طبقة `RelationResolver`.
22. **التكيف مع العتاد والإغلاق التلقائي للموارد:** ضبط خيوط المعالجة حسب أنوية المعالج وإغلاق المقابس والـ Sockets إجبارياً.

## الباب الثاني: الركائز المعمارية الست المتطورة (Production Pillars)

1. **Hardware-Adaptive Physical Core Detection:**
   * استكشاف ديناميكي للأنوية الفيزيائية للجهاز عبر `psutil.cpu_count(logical=False)` وتمريرها في `num_thread`.
2. **Managed HTTP Session & Auto-Closing Sockets:**
   * تجميع الاتصالات في `requests.Session` وإغلاقها إجبارياً داخل كتلة `finally:` لاسترداد المقابس والرام فوراً.
3. **13 Relational Covering Indexes:**
   * 13 فهرساً تغطوياً في SQL Server تمنع الـ Full Table Scans وتسرع الربط 10 أضعاف.
4. **Smart Adaptive OCR Router (`engine="auto"`):**
   * توجيه ذكي للنصوص المطبوعة نحو `PaddleOCR` ولخط اليد الصعب نحو `Qwen2.5-VL-3B`.
5. **Sliding-Window Document Chunking:**
   * تقطيع مستندات Word و PDF الضخمة لنوافذ سياقية متوازنة الذاكرة مع دمج النتائج مصفوفياً.
6. **FastAPI Enterprise REST Gateway:**
   * بوابة REST API كاملة وموثقة بـ Swagger عند `/docs` تدعم الرفع والاستعلام ومراقبة العتاد.

## الباب الثالث: طبقة الاستقبال والتوجيه الحتمي

* **كاشف امتداد الملفات (`src/ingestion/file_detector.py`):**
  يفحص امتداد الملف ويطابقه مع قائمة الامتدادات المدعومة (`.pdf`, `.docx`, `.csv`, `.xlsx`, `.png`, `.jpg`, `.jpeg`, `.webp`).
* **موجه المسارات (`src/ingestion/router.py`):**
  يحول نوع الملف إلى أحد المسارات الأربعة: `pdf_pipeline`, `image_pipeline`, `word_pipeline`, أو `csv_pipeline/excel_pipeline`.

## الباب الرابع: معالجات المستندات المتخصصة والتقطيع التدفقي

* **معالج ملفات PDF (`src/processors/pdf_processor.py`):**
  يميز بين الـ PDF الرقمي والـ PDF الممسوح ضوئياً؛ الرقمي يقطعه تدفقياً بحدود ذاكرة آمنة عبر `get_dynamic_batch_limit()`، والممسوح يحوله لصور بدقة عالية.
* **معالج مستندات Word (`src/processors/word_processor.py`):**
  يقرأ الفقرات والجداول الطبية ويقسمها لكتل سياقية تمنع فيضان نافذة السياق (Context Overflow).
* **معالج البيانات المنظمة (`src/processors/structured_processor.py`):**
  يقرأ جداول التحاليل والإحصائيات عبر Pandas ويولد ملخصاً متجهاً بدون الحاجة للنموذج اللغوي.
* **معالج الصور (`src/processors/image_processor.py`):**
  يضبط تباين الصورة (Autocontrast)، التدوير التلقائي (EXIF Transpose)، وتحويل الألوان لتسهيل القراءة البصرية.

## الباب الخامس: منظومة الرؤية الحاسوبية والتعرف الضوئي الهجين

* **محرك النصوص المطبوعة (`src/ocr/ocr_engine.py`):**
  مبني على `PaddleOCR` عالي السرعة، يدعم اللغتين العربية والإنجليزية، ويستخرج صفحات التقارير في أقل من ثانية واحدة.
* **محرك خط اليد الطبي (`src/ocr/handwriting_ocr.py`):**
  مبني على نموذج الرؤية المتقدم `Qwen2.5-VL-3B` لفك طلاسم خطوط الأطباء والجرعات الدوائية بدقة فائقة.
* **الموجه الذكي للـ OCR (`src/ocr/ocr_router.py`):**
  يفحص كثافة وثقة النص المطبوع أولاً؛ إذا كانت الثقة عالية يعتمدها فوراً، وإذا وجد نصوصاً مشوهة أو خط يد يوجهها للـ Vision LLM.
